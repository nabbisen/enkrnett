# 0.3.0

**Release candidate, 2026-11-27; not yet tagged.** The tag is made on the owner's authorization
(ROADMAP, release cycle). The wrap of milestone M3, *Installable*, on top of
[0.2.0](./0.2.0.md). For development and testing; not for operators. No router has run Enkrnett
yet, no release key exists, and no image is published: the *Open* table says what waits for the
owner's Tier 1 device and the legal basis.

## What it contains

| Area | Content | Chapter |
|---|---|---|
| Release index and keys | signify-format Ed25519 keys and signatures; the signed index with its sequence; the daily check and the check on request through the platform's downloader over HTTPS; the switch for a package install; `enkrnett-release` | 11 §1, 9 |
| Installing an update | The owner's *Update* after the screen's own step; download to RAM bounded by the index; SHA-512 and signature in one pass; the marker on flash; the root helper verifying again with `usign` and running `sysupgrade` with the configuration kept; the first boot reporting done or failed; the broken successor keeps the previous settings | 11 §2 |
| Reproducible build | The lock of every input (archives, packages with version and hash, toolchains, patches); images built from the lock with no live feed; the daemon, the UI and the images bit-identical between two builds and between two hosts; the release directory with hashes, lock, build report, source offer and the index to sign | 11 §3 |
| Guides | In English: install per Tier 1 candidate, set up, update, erase, recover, the expert install; under the word check | 5, 10 |
| Usability test | The M-7 plan: eight sessions with the guides alone, the facts the first unit settles, the pass criteria | 5 §5.1, 14 |
| Profiles | `update.min_free_kib` and `update.install_seconds` per device; the ELECOM light corrected to green | 5 |
| Stored data | The documents of 0.1.0, 0.2.0 and this release read by the current daemon (ENK-BASE-005) | 5 §5.3 |

## Review against the security chapters (ENK-SCOPE-004, ENK-GUEST-002)

The new operator-facing text of this release, the update screens (`update.*`) and the guides, was
read against chapters 2, 7, 11 and 12 §7. The update screen states the version, the duration,
that the Wi-Fi stops and that it cannot be undone from here, and names a failure by what the
device did (nothing changed; or installed but running the previous settings). The guides say
what is encrypted and what is not in the words of the status screen, never that something is
"secure"; the word check covers them. Nothing was found to change in the 0.2.0 text.

## Deviations to carry into the next amendment RFC

From stage 1: the update-check switch rides on `update/check` as `{enable_checks}`. From stage 2:
`last_result.reason` `install_failed`; the root side's second verification as design. From stage
3: the profile's `update` block; the download tree read by locked paths standing in for the
pinned mirror. From stage 4: ENK-INST-001's "every language" met in English only by the owner's
decision, the Japanese guides a future plan; the setup Wi-Fi's name has the form
`Enkrnett Setup XXXX` and the guides name it so.
