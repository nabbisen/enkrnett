# 2. Networks and separation

From RFC 002, as amended by RFC 007 (ENK-HARD-008), RFC 014 (read-backs, chapter 6), and RFC 016
(ENK-TOPO-006, ENK-HARD-006).

The device is a **routed access point**. Guests get their own network and reach the Internet and
nothing else. The operator manages the device through a separate management network. No
guest-facing interface accepts management traffic or platform administration.

## 2.1 Networks

| Network | Medium | Wi-Fi security | Addresses | Exists in state |
|---|---|---|---|---|
| Uplink | Ethernet | — | IPv4 by DHCP from the site router | Always |
| Guest | Wi-Fi | OWE, or OWE with Transition Mode (chapter 7) | Own IPv4 subnet, served by the device | `CLAIMED` |
| Management | Wi-Fi | WPA2-Personal and WPA3-Personal, key generated by the device | Own IPv4 subnet, served by the device | `PENDING`, `CLAIMED` |
| Setup | Wi-Fi | OWE with Transition Mode | Own IPv4 subnet, served by the device | `SETUP` |

States: chapter 4.

## 2.2 What may reach what

| From ↓ To → | Management UI and API | DHCP and DNS on the device | Internet | Site network | Guest clients | Management clients |
|---|---|---|---|---|---|---|
| **Guest client** | ✗ | ✓ | ✓ | ✗ | ✗ | ✗ |
| **Management client** | ✓ | ✓ | ✓ | ✗ | ✗ | ✗ |
| **Setup client** | ✓ | ✓ | ✗ | ✗ | — | — |
| **Uplink side** | ✗ | ✗ | — | — | ✗ | ✗ |

Management clients reach the Internet so that a phone does not route around a Wi-Fi network
without Internet. Setup clients do not: an unclaimed device gives Internet access to nobody.

## 2.3 Services reachable on the device

| Network | Reachable services |
|---|---|
| Guest | DHCP, DNS |
| Management | DHCP, DNS, management UI and API |
| Setup | DHCP, DNS, management UI and API |
| Uplink | None |

Anything else that answers is a defect. The daemon reads these facts back from the kernel and the
services after every change (chapter 6, ENK-CFG-023 to 026).

## 2.5 What separation does not do

Enkrnett states these limits to the operator and to guests (ENK-SCOPE-004; chapter 7 §4).

| Limit | Reason |
|---|---|
| A guest can still send broadcast frames to other guests. | All clients of one BSS share a group key. |
| Clients without OWE on a Transition Mode network are not encrypted. | By design of Transition Mode. |
| A fake access point with the same name is not prevented. | OWE has no authentication. |
| Traffic is protected on the radio link only. | Same. |
| Anyone who can touch the device can erase it. | Physical access (chapter 4 §8). |

The status says "blocked by this device" for what ENK-ISO requires and lists these limits. It
never says "isolated" or "secure" without qualification.

## 2.6 Hardware note

OpenWrt builds the MT7628 target without process jails and without position-independent
executables. On that target the separation rests on the firewall and the bridges alone. Device
profiles state this (chapter 5).
