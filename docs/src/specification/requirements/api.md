| ID | Requirement | Verification | RFC | Release |
|---|---|---|---|---|
| ENK-API-001 | The API shall live under the path prefix `/api/1/`. The integer is the API version; it changes only when an existing shape changes incompatibly, and the greeting states it. Paths are matched exactly. | Inspection | 015 | 0.1.0 |
| ENK-API-002 | Every request to a `POST` resource shall carry a JSON body, `{}` when the action has no parameters, with `Content-Type: application/json`; every response body shall be a JSON object, `{}` when there is nothing to say, as `application/json; charset=utf-8`. A `POST` without a JSON content type is refused with 415. | Test; cross-origin test (the preflight is refused) | 015 | 0.1.0 |
| ENK-API-003 | Reads shall use `GET` and change nothing. Everything that changes state shall use `POST`. Any other method answers 405. | Test with `PUT`, `PATCH`, `DELETE`, `OPTIONS` | 015 | 0.1.0 |
| ENK-API-004 | Field names shall be `snake_case`. Every field of a shape shall always be present; `null` means "not known" or "not applicable" and appears only where this RFC says so. | Schema test | 015 | 0.1.0 |
| ENK-API-005 | A request with a field this RFC does not define, a value of the wrong type, or a body on a `GET` shall be refused with 400 and the field named. Nothing is ignored silently. | Test | 015 | 0.1.0 |
| ENK-API-006 | Durations shall be integers in seconds relative to the moment of the response: `*_in` for a remaining time, `*_ago` for an elapsed time, `*_seconds` for an estimate. The API shall never send a date or a clock time. | Inspection | 015 | 0.1.0 |
| ENK-API-007 | The API shall send no text meant for the operator's screen. Every state is an enumerated value and every error a code; the UI holds the wording in each language. The optional `message` of an error is English, for developers, and the UI never displays it. | Inspection | 015 | 0.1.0 |
| ENK-API-008 | The session token shall be sent in the request header `Enkrnett-Session`. Cookies and the `Authorization` header are never read (RFC 003 ENK-SEC-010). | Test | 015 | 0.1.0 |
| ENK-API-009 | A shape shall be defined once (RFC 015 §4) and, where it appears inside another shape, embedded whole. | Schema test | 015 | 0.1.0 |
| ENK-API-010 | A resource that the current state does not offer shall answer 403 `wrong_state` with the current state, whether or not a session is presented. A resource that needs a session and gets none, or an ended one, shall answer 401 `no_session`. | Test of every resource in every state | 015 | 0.1.0 |
| ENK-API-011 | The greeting shall be exactly the `greeting` shape: `product`, `api`, `state`, `languages`, `development` (ENK-HARD-007), and `connection` with `network` and `security` (ENK-OWN-022). Nothing else is readable without a session. | Test (RFC 004 ENK-AUTH-007) | 015 (amended by 016) | 0.1.0 |
| ENK-API-012 | While `update.state` is not `idle`, every `POST` except `logout` shall answer 409 `update_in_progress`. | Test | 015 | 0.1.0 |
| ENK-API-013 | These shall be the only resources. Adding one requires an RFC. | Test: every other path under `/api/` answers 404 `unknown_resource` | 015 | 0.1.0 |
| ENK-API-014 | `POST settings` shall be the only way to change the desired document. It carries the whole document except `country` and `management.key`, with the `version` the client last read. A `version` that is not the current one is refused with 409 `version_mismatch` and the current `settings`. A retried save therefore meets `change_pending` (with the change) or `version_mismatch` (with the saved document), and no change is applied twice. | Test, including a retry after a lost response | 015 | 0.1.0 |
| ENK-API-015 | `claim/confirm`, `restart`, and `erase` shall send their response before the network change they cause, and the daemon shall wait at least 2 seconds after sending before it acts. | Test with a slow client | 015 | 0.1.0 |
| ENK-API-016 | Every `/api/` response shall carry `Cache-Control: no-store` (RFC 007 ENK-SEC-015). | Header inspection | 015 | 0.1.0 |
| ENK-API-017 | At most one claim proposal shall exist, kept in memory and discarded when the claim session ends. A second `claim/check` replaces it. | Test | 015 | 0.1.0 |
| ENK-API-018 | Every error response shall use this shape and one of these codes. A new code requires an RFC. | Schema test | 015 | 0.1.0 |
| ENK-API-019 | Validation shall report every failing field at once, not the first only. | Test with two invalid fields | 015 | 0.1.0 |
| ENK-API-020 | `password` shall validate the new password first (400 `invalid`), then check the current one. A `wrong_password` answer shall take the same time whatever the wrong value was. | Timing test | 015 | 0.1.0 |
| ENK-API-021 | Once the health check of such a change has passed, the daemon shall disconnect every station of the management network (`hostapd.* del_client` with deauthentication) and only then enter `waiting_confirmation`, so that any later request proves a new association with the new name or key. | Test | 015 | 0.2.0 |
| ENK-API-022 | The change shall be confirmed by the first request with a valid owner session that arrives on a connection accepted after the disconnection of ENK-API-021 completed, while the change is `waiting_confirmation`. There is no separate confirmation action. | Test: a request received before the disconnection does not settle the change; the first one after it does | 015 | 0.2.0 |
| ENK-API-023 | `POST management-key` shall answer with the `change` shape and, beside it, a `management_key` field holding the new key, because the operator needs the key before the reload and cannot read it afterwards. This is the only compound response. | Inspection | 015 | 0.2.0 |
| ENK-API-024 | `GET /` and `GET /index.html` shall serve the UI's entry page with `Cache-Control: no-store`; every other UI file shall be named with a hash of its content and served with `Cache-Control: max-age=31536000, immutable`. | Inspection (RFC 003 ENK-MGMT-005) | 015 | 0.1.0 |
| ENK-API-025 | Every response, API or file, shall carry: `Content-Security-Policy: default-src 'self'; img-src 'self' data:; frame-ancestors 'none'; base-uri 'none'; form-action 'none'`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Resource-Policy: same-origin`. No `Access-Control-*` header is ever sent. | Header inspection (RFC 003 ENK-SEC-011, 012) | 015 | 0.1.0 |
| ENK-API-026 | A path outside `/api/` that is not a UI file shall serve the entry page (the UI routes on the client) with the headers above. | Test | 015 | 0.1.0 |
| ENK-API-027 | The daemon shall answer `status` from readings at most 2 seconds old and shall not query ubus more than once per 2 seconds for it, whatever the number of clients. | Test with two clients polling | 015 | 0.1.0 |
| ENK-API-028 | The daemon shall log to the platform's system log (`logd`, in memory) and shall write no log file of its own. | Inspection (D-15; RFC 010) | 015 | 0.1.0 |
| ENK-API-029 | It shall log, one line each: session created and ended (kind, cause); login refused (count of consecutive failures); claim started, confirmed, made final, abandoned; change started, settled, undone (id, kind, reason, detail); drift detected; update checked, started, failed, done; erase and restart requested; every 500 with its reference. | Inspection after exercising every function | 015 | 0.1.0 |
| ENK-API-030 | A log line shall contain no station address, no client address, no name entered by the operator, and nothing listed in RFC 007 ENK-SEC-016. | Search of the log after exercising every function | 015 | 0.1.0 |
| ENK-API-031 | A field may be added to a shape, and a value to an enumeration, only together with the UI release that handles it (they ship together, ENK-MGMT-004). A client that is not the device's UI shall treat an unknown enumeration value as "unknown" and shall not act on it. | Inspection | 015 | 0.1.0 |
| ENK-API-032 | Removing a field or changing a meaning shall increase the API version; the previous prefix is retired in the same release. The device never serves two API versions. | Inspection | 015 | 0.1.0 |
