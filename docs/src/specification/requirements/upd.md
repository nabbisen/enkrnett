| ID | Requirement | Verification | RFC | Release |
|---|---|---|---|---|
| ENK-UPD-001 | The device shall check the release index at most once a day by itself and on request, fetching the index and the image through the platform's downloader over HTTPS to the project's host. The check shall send no identifier of the device, the operator, or the configuration; the request is the same for every device of the same profile. Authenticity rests on the signatures of ENK-UPD-003, not on the transport. | Network capture | 013 (amended by 016) | 0.3.0 |
| ENK-UPD-002 | The device shall start an update only when the owner presses *Update* in the management UI, after a screen that states the version, the baseline change if any, the duration, and that the Wi-Fi stops meanwhile. | Inspection; M-7 | 013 | 0.3.0 |
| ENK-UPD-003 | Before writing, the device shall verify: the signature of the index and of the image against an embedded key; that the image is for this device profile; that the baseline is the same or the designated next; that free memory exceeds the image size plus 16 MB; and that no transaction (RFC 011) is pending. Any failure shall stop the update with one sentence of reason, writing nothing. | Test for each condition | 013 | 0.3.0 |
| ENK-UPD-004 | The update shall carry over the owner, the management key, the desired document, and the device identifier (ENK-BASE-004), and shall not carry over logs, sessions, or snapshots. | Test | 013 | 0.3.0 |
| ENK-UPD-005 | On the first boot after an update the daemon shall verify the carried state (format versions, ENK-BASE-005), run the health check of RFC 011, and then report the update as done. If the health check fails, the device shall keep serving the last known configuration, mark the update as failed, and say so on the status screen. | Test with a deliberately broken successor | 013 | 0.3.0 |
| ENK-UPD-006 | The device shall not promise a firmware rollback it cannot perform. On single-slot devices the only way back is a new update or the recovery of the device profile; the UI shall say "this cannot be undone from here" before the update starts. | Inspection | 013 | 0.3.0 |
| ENK-UPD-007 | *Update* and *Upgrade* are the project's words (RFC 001 §4.2). The operator sees *Update* for both; when the baseline changes, the confirmation screen adds "This one takes longer and restarts the Wi-Fi twice." | Inspection | 013 | 0.3.0 |
| ENK-UPD-008 | A development build or an image installed by other means shall not be offered updates from the project's index unless the owner enables it in the details screen. | Test | 013 | 0.3.0 |
| ENK-UPD-009 | The release index shall carry a sequence number that increases with every publication. The device shall keep the highest sequence it has accepted, shall refuse an index with a lower sequence, and shall offer and install only a release whose version is greater than the installed one. An expert may install any release by other means (ENK-UPD-008). | Test with a replayed index and with an index that offers the installed or an older version | 016 | 0.3.0 |
