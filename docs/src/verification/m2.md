# Milestone M2: what is verified so far

M2's exit condition (ROADMAP): the tests derived from RFC 002 and the OWE and configuration RFCs
pass; the operator configures the guest network; separation and hardening are in place; the status
says what is protected and what is not. This page grows with the stages of M2.

## Stage 1: the transaction (2026-11-26)

| Suite | Where | Count | Covers |
|---|---|---|---|
| Transaction tests against the mock | `crates/enkrnettd/tests/changes.rs` | 9 | 202 while applying and settled after (ENK-CFG-010); the marker on flash before the platform is asked (ENK-CFG-006); one change at a time with the state of the first (ENK-CFG-011); a failed health check undone with reason and detail, the previous document back (ENK-CFG-009); a management change disconnects, then waits, a request on the same instant or without the owner's session does not confirm, the first owner request on a later connection does and already sees `settled` (ENK-API-021, 022); not confirmed in 600 s on the monotonic clock → undone `not_confirmed` (ENK-CFG-008, 012); a request after the deadline cannot confirm; the key replacement's compound response (ENK-API-023); restore keeps the version; a marker found at start-up → `undone` with reason `restart`, numbering continues |
| Store | `crates/enkrnettd/src/store/tests.rs` | 3 new | Marker written, read, removed; an unreadable marker still counts; files mode 0600 |
| Browser harness | `tests/browser/` | 14 | Unchanged tests pass with the asynchronous change and the polling display |
| VM | `tests/vm/claim.sh` | — | On the packaged service: a guest change accepted as `applying`, settled by the health check, the marker removed; a management name change accepted, `management_disconnected`, `change_waiting_confirmation`, confirmed by the next request through the tunnel, `settled`; `hostapd.enk-mgmt` carries the new name; the stored document holds it |

Not yet covered: a real station losing its association on `del_client` and the owner rejoining
by hand (M-4a, the Tier 1 device); the undo on the VM with a health check that really fails;
power loss between the marker and the reload (the restart path is covered against the mock).

## Stage 2: separation on the platform (2026-11-26)

| Suite | Where | Covers |
|---|---|---|
| Platform unit tests | `crates/enkrnettd/src/platform/tests.rs` | `/proc/net` parsing with the kernel's byte order, IPv6 sockets as "every address", the exposure rule for the UI's ports, the bridge-port flags from sysfs |
| Model | `crates/enkrnett-model/src/plan/tests.rs` | The bridges and addresses to read back per phase |
| VM, four simulated stations | `tests/vm/isolation.sh` | g1 and g3 on the OWE BSS, g2 on the open BSS, m1 on the management network with WPA2. A guest cannot open the site host or ping the site router, reaches the Internet, finds DNS (and DHCP) and nothing else on the device, cannot reach the UI on port 80 or the daemon's port, cannot reach another guest on the same BSS, across the Transition Mode pair in either direction (M-8 row 6, now holding), or routed through the device; no IPv6 on the guest bridge or between guests. The management station reaches the UI and the Internet, not the site host, not a guest, not the guest network's DNS instance. The greeting names the management network and WPA2 for the WPA2 station; a guest station gets nothing from the API. Two bridges; every bridge port isolated; a DNS listener on each network's address; no WPS in the generated hostapd configuration; the management network not hidden. The status counts 2 encrypted and 1 unencrypted guest and 1 management client; the hardening report says the VM's dropbear breaks ENK-HARD-002. |

Found by this run and changed: a management station could reach the DNS instance that serves the guest network, on the device's guest-side address. The DNS and UI rules of each zone now accept only the network's own address as destination (`plan::zone_rules`).

What the VM cannot show: a second radio (ENK-ISO-002 across radios), the group-key broadcast
path of a real radio (chapter 2 §5), a real site network behind the uplink (ENK-ISO-005 by
inspection of the `wan` input chain, which the image owns), failsafe mode (ENK-HARD-003).
