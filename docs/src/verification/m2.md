# Milestone M2: what is verified so far

M2's exit condition (ROADMAP): the tests derived from RFC 002 and the OWE and configuration RFCs
pass; the operator configures the guest network; separation and hardening are in place; the status
says what is protected and what is not. This page grows with the stages of M2.

### Found by the reproducible VM and fixed

| Found | Fix |
|---|---|
| The daemon asked for its restart through the `rc` ubus object, which rpcd provides; the measurement VM had LuCI and rpcd, a minimal image has neither, and the request failed with "not found" (`service_restart_failed`) | `restart_service` sends a `config.change` event for the package `enkrnett` to procd's own `service` object; the init script's reload trigger makes it `restart`. The `rc` entry left the ACL |
| The generated `wifi-device` sections put `mac80211_hwsim` on 6 GHz (EHT80) with the current wifi-scripts, where hostapd refuses the open BSS of Transition Mode ("Pre-RSNA security methods are not allowed in 6 GHz"); the measurement VM had been generated on 2.4 GHz | `prepare.sh` sets every radio to the band the VM profile declares (2g, channel 6, HT20), as a device image ships its radios |
| `package.sh` disabled uhttpd unconditionally; without LuCI the script died before the reboot that lets ubusd read the ACL | Guarded; the chain stops after a failed foundation step instead of reporting the fallout |
| `package.sh` reached the VM while the reboot of `prepare.sh` was under way | It waits for ssh to answer; the chain pauses after `prepare.sh` |
| In CI the browser harness failed on WebKit since stage 2: the last Chromium test (the Japanese setup screens) left its claim session open, and the device rightly refused the next Start for five minutes | The test finishes its claim like the others; the rule is in `helpers.ts` |
| `.github/workflows/vm.yml` was refused by GitHub: two unquoted scalars with a colon and a trailing word | Quoted |
| On the runner the daemon found no profile for the board: Ubuntu's QEMU build labels the machine "Ubuntu 26.04 PC (i440FX + PIIX, 1996)", so OpenWrt's board name was `qemu-ubuntu-26-04-pc-i440fx-piix-1996`, not the `qemu-standard-pc-i440fx-piix-1996` the VM profile names; procd respawned the daemon every 5 s and the claim met no listener | The launcher pins the SMBIOS vendor and product (`-smbios type=1`), so the board name is the same on every host; the chain saves the daemon log after a failed foundation step too; `claim.sh` fails with "the daemon did not start" and the board name instead of an HTTP 000 |

## M2 exit

The exit condition of M2 is "the tests derived from RFC 002 and the OWE and configuration RFCs
pass". On the VM they do (chapters 2, 6, 7: `isolation.sh`, `drift.sh`, `renumber.sh`,
`claim.sh`, and the changes of `changes.rs` and `effective.rs` against the mock). What the VM
cannot show is listed in the release notes (`docs/src/releases/0.2.0.md`, *Open*): the Tier 1
device, the real client matrix, PMF read back from hostapd.
