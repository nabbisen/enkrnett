# Milestone M1: what was verified

M1's exit condition (ROADMAP): the tests derived from RFC 003 (management channel) and RFC 004
(ownership, credentials, authorization) pass; daemon and UI run together on the virtual machine
and on the Tier 1 device; a device can be claimed and reset. This page records what ran, where,
and what it did not cover. The Tier 1 device part waits for hardware (owner side); everything
else below was observed on 2026-11-26.

## 2. Against OpenWrt on the x86-64 VM (`tests/vm/`)

The VM runs OpenWrt 25.12.5 with `netifd`, `hostapd` (mac80211_hwsim), `dnsmasq`, and `firewall4`.
The package built from `openwrt/package/enkrnett` with the x86/64 SDK of the lock is installed
with `apk`; after a reboot `procd` starts the daemon as user `enkrnett` with no capability.

| Script | What it did | Result |
|---|---|---|
| `package.sh` | Build the package, install, reboot | Installed files as the Makefile lists; user created by `USERID`; service running, uid 1900, `CapEff` all zero; listener on 192.168.207.1:8080; the owned firewall redirect of port 80 present in `fw4`'s `dstnat` chain |
| `contract.sh` §RFC 003 | Host check, security headers, no CORS, `OPTIONS`, entry page `no-store`, content type, unknown resource | 14 checks passed |
| `contract.sh` §RFC 004 claim | SETUP after a fresh install; `status` and `login` refused by state; claim without session; one client at a time; common password; duplicate JSON key; confirm before check; the key's form; PENDING; the claim resources gone; the management BSS on the air; no setup section left | 16 checks passed |
| `contract.sh` §RFC 004 sessions | Five wrong passwords, the sixth attempt refused with `429`, `retry_in` and `Retry-After` agree; login after the delay; the fifth session ends the first; `status`, `management-key`, `device`; logout | 13 checks passed |
| `contract.sh` §Erase | Erase with the wrong password refused; erase accepted; the device reboots; the marker consumed by `boot()`; no owner record on flash; the init script's log line; the setup network back; SETUP again; the old password opens nothing | 8 checks passed |

Total on the real platform: 51 checks, every one passed, including Erase through a real boot on the
package path.

## 3. Found by these runs and fixed

| Found | Fix |
|---|---|
| `procd` applies a capabilities file only inside a `ujail`; a plain instance started with no capability and could not bind port 80 | The daemon listens on 8080 on the management address; the owned firewall sections redirect port 80 of the management interface (chapter 6 §7 note; `plan::LISTEN_PORT`) |
| The erase path's `uci commit` handed the four owned files back to root; the daemon then could not write them | The init script restores owner, mode, and the sticky directory at every start |
| `retry_in` was rounded down, so a client that waited exactly that long could be refused once more | Rounded up (`clock::seconds_until`) |
| A claim-flow test asserted a deferred platform call right after the state changed (flaky) | The test waits for the call |
| The rewritten configuration files and the owner record were world-readable | Written with mode 0600 (`store::write_private`); the fix recorded for stage 4 had not actually landed, found again by the M2 stage 1 VM run |
