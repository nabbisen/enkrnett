# Milestone M3: what is verified so far

M3's exit condition (ROADMAP): a non-expert installs, sets up, updates, and resets a Tier 1 device
with the guides, in English and Japanese; the usability test passes; update and upgrade are
tested. The device and the legal basis are the owner's side; what does not need them is built
first and recorded here stage by stage.

### On the real platform (`tests/vm/update-check.sh`)

The x86-64 VM from `tests/vm/image.sh`, the package built from the tree (`package.sh`), a claimed
device (`claim.sh`). The host makes a test key and a signed index with `enkrnett-release`, and
serves it over HTTPS with a certificate authority made for the run; the VM gets that authority in
`/etc/ssl/certs`, the host name in `/etc/hosts`, and the test key in `/usr/share/enkrnett/keys`.
The index URL goes through `uci set enkrnett.main.update_index` and the init script.

| Checks | Result |
|---|---|
| The tool verifies what it signed and refuses a stranger's signature; `uclient-fetch` reaches the host over HTTPS with the test authority | 3 passed |
| A package install has checks off; version and baseline as the daemon's (ENK-RLS-003); no fetch while off; the switch and the first check in one request; `ok`; the release offered with size and baseline; state idle; the sequence on flash (ENK-UPD-009); `index_verified` and `update_checked` logged (ENK-API-029) | 15 passed |
| A replayed older index `stale_index`; a changed index under the old signature `bad_signature`; a stranger's signature `bad_signature`; a signed document that is not an index `bad_index`; nothing offered after the refusals; a plain `http://` URL not tried, `unreachable` with the reason in the log; the server gone, `unreachable` | 8 passed |
| The VM as it was: checks off, URL, authority, key, host name removed | 1 passed |

The script is in the chain (`run-all.sh`, after `drift.sh`) and so in CI's `vm` workflow.

### Footprint

`openwrt/build-mips.sh`: the daemon 274 KiB of 300 (xz estimate; 240 at 0.2.0). The first build
with the check was 287: `std::process::Command` cost about 25 KB raw for the one program the
daemon runs, so the downloader is started with `posix_spawn` through `libc`
(`platform/spawn.rs`). Ed25519 itself is about 12 KB raw.

### Found by these runs and fixed

| Found | Fix |
|---|---|
| The first VM run answered `unreachable` to everything: `claim.sh` installs the daemon, the UI and the profile into the installed package, not the init script, so the daemon ran without `--update-index` | The chain rebuilds the package (`package.sh`) before `claim.sh`, as CI does; locally the package had to be rebuilt |
| `package.sh` built the package without the `keys/` directory the Makefile now installs | `package.sh` and `build-mips.sh` create it (empty until a key exists); the Makefile copies it only when present |
| The browser harness runs the daemon with `--development`, which ENK-UPD-008 now keeps from checking | The details test turns the checks on first, which covers the switch in the browser |
| The daemon cannot read `/etc/config/enkrnett` (root's, mode 0600 from `INSTALL_CONF`), where the index URL lives | The init script reads the option and passes `--update-index`; the daemon reads no root-owned file |

### Deviations for the next amendment RFC

- `update/check` accepts `{"enable_checks": true|false}`: the switch of ENK-UPD-008 has no
  resource in the accepted API (ENK-API-013), so it rides on this request.
- The automatic check waits for a plausible wall clock (2025 or later): a router without a
  battery boots in 1970 and cannot judge "once a day" until the time is set.
